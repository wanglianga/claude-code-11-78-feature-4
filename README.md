# 燃气观测一致性与处置工具（离线）

面向市燃气监管中心的**纯前端离线**应用：在无网络环境下，对巡检轨迹、阀井读数、设备台账、
施工清单与整改回执做装载签名、语义对齐、版本化规则核验、告警双路线压缩、证据图回溯与离线处置同步对照；
并提供**汛期燃气井进水因果推断子系统**——专家因果图编辑、证据语义标注、依赖簇合并的支持/反驳区间计算、
缺证沿图传播与结论稳健性对比，结论只表述为支持 / 反驳 / 证据不足。

技术栈：**React 18 + TypeScript + Vite + IndexedDB + WebWorker**，运行期无后端、无外部 CDN，
全部数据保存在浏览器 IndexedDB（库名 `gas-consistency-db`）。

## 3. 使用与验证流程

1. 登录后进入 **「装载器与签名」**，点击「装载确定性场景（三阶段样例）」：
   原始记录（含采样/到达时间、可信度）写入 IndexedDB，并对业务字段固化 SHA-256 签名；可点击「重新验签」。
2. 点击「交给 WebWorker 执行核验」（或进入 **「时序核验器」** 点「运行双路线核验与压缩」）：
   Worker 在后台线程完成对齐 → 分版本核验 → A/B 双路线压缩 → 见证边界校验 → 证据图 → 同步报告，产物全部落 IndexedDB。
3. 依次查看：
   - **语义对齐器**：别名映射、bar→kPa / L/s→m³h 单位换算、GCJ02→WGS84 坐标修正、施工包围盒判定；
   - **规则浏览器**：RV-2026.1 与 RV-2026.2 两版规则参数与变更说明；
   - **压缩事件双路线**：任选事件进入调查页，路线 A 直接读不可变成员关系；
     路线 B 现场解码见证（显示解码耗时、槽位/字典码、边界校验），两页面可交叉跳转；
   - **证据图**：观测→告警→事件→回执的 SVG 证据链，可按事件筛选可达子图；
   - **处置簿**：离线行动全量保留（含 baseVersion 与同步状态），可继续提交批注/签收/关闭/重开；
   - **同步对照器**：双路线载荷体积对比、逐事件 A/B 等价性表、离线补传冲突的本地/远端原值与解决按钮；
   - **自检与验证**：19 项断言一键复算（与 `npm test` 共用 `src/core/selfcheck.ts`）。
4. 进入侧边栏 **「因果推断（汛期进水）」**，在因果图编辑器页点击「装载汛期因果样例（确定性数据）」，
   随后依次使用：因果假设图编辑器（⑩）→ 证据语义标注册（⑪）→ 支持/反驳与主张区间（⑫）
   → 缺证传播器（⑬，可切换故障期/恢复后视角）→ 结论稳健性台（⑭）；
   在编辑器页可「应用后补维修结论（生成 v2）」并「冻结当前版本并生成处置理由」，验证版本链与冻结引用。

## 4. 两条压缩路线（核心设计）

| 维度 | 路线 A：规范化不可变成员—事件关系 | 路线 B：压缩成员见证 |
| --- | --- | --- |
| 存储 | 每个成员一条 `MembershipRecord`（事件 ID、告警 ID、逐成员贡献、版本戳记，`immutable=true`） | 每个事件一个 `CompressedWitness`：设备+连续时间窗槽位（5 分钟粒度）+规则版本编码、内容寻址告警引用、贡献字典码、`witnessHash` |
| 调查 | 直接索引读取，无解码等待 | 查询时 `decodeWitness()` 确定性解码，并强制 `verifyBoundary()` 检查相邻槽位无遗漏成员 |
| 重算 | 规则换版只重算受影响窗口，新事件经 `parentEventId` 挂接旧事件，旧关系永不改写 | 同左；新见证独立哈希，旧见证保留 |
| 体积 | 索引/同步量较大 | 载荷更小（同步对照页给出实际字节与节省比例） |
| 防篡改 | 关系不可变 + 告警内容寻址 ID | 见证体 SHA-256 哈希，篡改引用后槽位解码直接抛错 |

**两条路线对任何聚合事件都还原相同的成员来源、严重度与逐成员贡献**；不存在只含摘要、
无法还原成员的快照（自检 EV-3 强制断言）。

## 5. 内置样例场景（确定性，无随机数）

同日（2026-11-23）三阶段：

- **阶段一 08:00–12:00 网络漂移 × 施工扰动重叠（RV-2026.1）**
  - VW-001 读数 09:15 延迟 25 分钟、10:30 乱序到达；09:15→10:00 出现 45 分钟采样缺口；
  - 施工区 CZ-01（09:00–11:00）内 11:00 回落跳变按施工清单 `suppressKinds=jump` 抑制，
    降级为 info 但**保留为成员、不批量关闭**；区外 PS-002 的 09:30 跳变正常判罚；
  - VW-001 观测状态 `open` 与台账声明 `closed` 持续矛盾，关联缺失上游 ID 的整改回执 RC-001。
- **阶段二 12:00 规则换版 RV-2026.2（局部重算）**
  - 缺测 30→20 分钟、跳变量程比 0.40→0.25 且升 critical、矛盾容忍 10→5 升 critical、逾期宽限 60→30 分钟；
  - 新增告警样例：PS-002 13:00/13:10 跳变（v1=2 → v2=4）、VW-001 13:30 缺测（v1=1 → v2=2）、
    RC-003 回执延迟 40 分钟（v1 不逾期 → v2 逾期）；v2 事件全部带 `parentEventId` 重算链。
- **阶段三 16:00–18:00 离线补传与同步冲突**
  - FS-003 16:00 缺测、16:20/16:40 读数延迟 70 分钟补传（标注 backfilled）；
  - 巡检端 16:40 离线批注、17:10 基于过期 baseVersion 重开监管端已关闭事件；
  - 同步对照器产出 3 项冲突（事件状态、行动版本、回执 RC-001 状态），双方原值均保留。

## 6. 汛期因果推断子系统（专家因果图 + 区间似然传播）

针对汛期前夕多个低洼小区燃气井同时出现进水传感器缺报、浓度延迟与工单逾期，子系统拒绝把现象简单归并为
“暴雨影响”，而是把**候选根因、机制、可观测征兆、前置条件与下游影响**组织为有向因果图，逐条主张独立检验。

路线选择依据：本场景为**新小区、稀少历史裁定事件**，历史裁定覆盖度不足以训练概率图模型（且存在雨季分布漂移
与样本选择偏差），因此采用**专家维护的因果图 + 区间似然传播**：解释清晰、可显式保留缺证；代价是主张节点与
适用前提需要专家持续校正（编辑器与推断版本链即为此设计）。

### 6.1 五个界面（侧边栏「因果推断（汛期进水）」分组）

| 页面 | 能力 |
| --- | --- |
| ⑩ 因果假设图编辑器 | 分层 SVG 因果图（根因/机制/征兆/前提/影响）；增删节点与主张边、维护适用前提与“应有反证键”、停用边；应用后补维修结论生成 v2；维护推断版本链与冻结处置理由 |
| ⑪ 证据语义标注册 | 每条雨量/断电/心跳/排水/浓度/工单/维修证据的发生**区间**、来源可靠度、依赖簇、支持或反驳哪条主张；提供证据列表与依赖簇两种视图 |
| ⑫ 支持/反驳与主张区间 | 先簇内合并再逐主张计算支持量、反驳量与无法判定区间，展开可看每簇合并明细与缺证反证；根因结论仅输出支持/反驳/证据不足 |
| ⑬ 缺证传播器 | 沿图说明上游通道故障把哪些下游主张由“无反证”降为“未知”，并区分“通道屏蔽缺证”与“本应出现却缺失”的缺证反证；展示安全判断的不确定性传导；可切换故障期/恢复后视角 |
| ⑭ 结论稳健性台 | 删除来源簇、扩大时间容差、替换来源可靠度等情景下的根因翻转矩阵与翻转计数 |

### 6.2 四条强制规则的落地方式

1. **同依赖簇不叠加**：雨量站、网关、供电监测共用配电箱 A 且 14:40 同时失联，证据 CE-01/CE-02/CE-03/CE-04
   同属簇 `CL-BOX-A`。计算器先在簇内合并为 1 个簇贡献（共链路簇权重封顶 0.6），再计入主张，
   **不会叠加成“暴雨”的双重支持**（见 ⑫ 页 CL-STORM-FLOOD 展开明细）。
2. **排水后浓度仍升高 → 仅积水假设受反驳**：16:20 排水完成、供电恢复后，浓度 16:30–17:30 仍由 18%LEL
   升至 41%LEL（CE-08，通道已恢复的直接反证）；同时“传感器恢复上报”在通道恢复后仍缺失，构成缺证反证。
   缺证传播器把「仅积水导致异常（H-WATER-ONLY）」转为**受反驳**，并经因果链把不确定性传导给“恢复供气”
   安全判断：禁止按原假设恢复供气。
3. **仅接收时间的证据不能排除假设**：外部气象复核 CE-13 只记录 18:30 接收、链路延迟未知，标注册保留
   16:30–18:30 整段区间；扩大任何时间容差该区间都与分析窗相交（不会被时间窗剔除），且因其延迟未知，
   任何情景下都不能仅凭该点证据把“暴雨导致进水”判为反驳，最多降为证据不足。
4. **维修结论触发新版本、冻结理由持续可溯源**：次日维修结论 CE-14 确认网关有独立备用电池，
   前置条件 P-BOX 改写为不成立、主张 CL-POWER-GW 停用、新增 CL-FLOOD-GW，系统生成推断版本 **IV-v2**
   （父版本 IV-v1 不被改写）；已冻结的处置理由仍引用 IV-v1 当时的图快照与证据范围，仓储层对冻结版本的
   同 ID 写入直接抛错拒绝。

### 6.3 结论纪律

- 任何根因在任何情景下的结论只取 **支持 / 反驳 / 证据不足**；最高分仅作为待验证解释，
  不直接视作已完成根因认定。
- 因果子系统数据独立存储于 IndexedDB 新对象仓库（`causal_graph` / `causal_evidence` / `causal_clusters`
  / `causal_versions` / `causal_rationale`，DB 升级至 v2，旧数据自动迁移）。

## 9. 离线与数据说明

- 应用不发起任何网络请求；「远端快照」为 `sync.ts` 中确定性的模拟数据，仅用于离线冲突演示；
- 清空浏览器 IndexedDB 或点击装载器页「清空工作区」即可重置全部数据；
- 所有时间为固定 ISO 字符串（+08:00），场景可完整复现。
